## Accepted interface and its limits

The dedicated post-freeze tool supplies only the newly registered holdout
experiment ID. A still checks the frozen original OPT family/threshold
protocol, immutable dataset/representative/split identities, both discovery
Results and reviews, and the derived holdout Spec before a worker can read
holdout rows. Method sensitivity is outside that frozen validation. A genuine
method or stop choice must remain visible and cannot be forced into it.

The scoped wrappers retain one original parent deadline across adaptive,
finalization and holdout sessions. A's 120-second worker and remaining
360-second aggregate discovery-plus-holdout compute caps are also retained.
Deadline checks around SQLite are cooperative rather than atomic real-time
transaction guarantees; the POSIX parent process-group timeout is the outer
bound. The private-hook lock does not make unrelated direct A invocations
safe to run concurrently. Native Windows is rejected by the holdout adapter;
actual execution uses a compatible POSIX host such as the checked WSL setup.

The durable claim guarantees one attempt **per frozen run**, not one attempt
globally across hosts or new runs. The team coordinates one actual validation
separately. Export reads already persisted Results and never recomputes science.
A trace/export failure remains a failed workflow even if science committed:
preserve that Result and inspect the recorded failure, without another
computation. Portable scientific evidence alone cannot authorize execution,
prove original CLI success, or attest a provider/model identity or OS sandbox.
