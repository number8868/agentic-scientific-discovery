# NOVA-MAT 自测与效用验证计划

版本：1.0 · 2026-10-05。状态：设计审查通过（仅方案，见 [审查记录](SELF_TEST_REVIEW.md)）；案例、运行器与执行预算待实现/批准。不是已运行结果或科学预注册。本文只定义未来工程自测，不授权模型调用、科学计算、registry 写入或 holdout 访问。所有结论必须以实际保存的原始记录为准。

## 1. 决策边界与已知证据

本计划把“B 范围”限定为运行器、编排、接口/格式验证、追踪、计时、失败恢复和报告；“A 批准”限定为科学测试题、参考答案及允许解释、单位/领域判定、科学结论和任何真实数据/科学运行。双方均不能以工程批准替代科学批准。若题目涉及真实 JARVIS 数值、科学引擎、冻结协议、split 或 holdout，必须另有 A 明确书面批准；本自测不需要也不接触 holdout。

已有证据不能支持多角色优势：2026-10-05 比较成功完成 84 次请求、36 个 arm evaluations，六个工程案例各重复两次；等预算三轮比较中，多角色对单角色自审的平均严格分数差为 −8.33 个百分点，六案例簇 bootstrap 95% 区间 [−20.24, 0.00]，符号检验 p=0.5；节省时间平均 0.719 秒，区间 [−1.466, 2.904] 秒，均未建立优势。审计发现严格得分还受答案类型/标签格式失配影响：正确数值以字符串表达、正确标签大小写不同；但一次真实比值算错也存在。故不得把旧分数差说成科学推理差异，也不得忽略格式契约缺陷。完整背景见 [旧比较报告](results/quality_comparison_20261005/README.md) 和 [旧基准协议](QUALITY_BENCHMARK.md)。

要分别报告三个不可互换的终点：

1. **工程可靠性**：成功完成、合法调用、正确持久化、超时/取消/重试的可追溯性。可靠不等于回答正确。
2. **证据解释质量**：计算、证据引用、单位、冲突处置及结论边界是否正确。结构化字段合格不等于解释文字正确。
3. **原生工作流科学效用**：真实科学证据是否改变下一步选择并产生有用新证据。合成决策包或 SDK 对比不能证明这一点；须另做经 A 批准的原生工作流研究。

本协议直接比较的是“并行独立 Planner + Skeptic，再由 PI 综合”的**完整方案包效应**，不是单独证明 specialist 身份、并行性或 PI 拆分各自的因果效果。计划中的单角色臂为初稿→自我批判→最终稿；并行臂的 Skeptic 必须先独立读相同原始 packet，不能看到 Planner 草稿，PI 后续可看到 Planner 与 Skeptic 两份结果。可另行预注册 serial-role ablation 或路由测试，但不得将其说成已实现/已测量。

## 2. 主要问题与冻结对照

主要问题：在同一模型、同一三次 SDK turn 预算、同一案例原始证据和受控并行条件下，并行双专家+PI 是否比单代理自审更快，同时保持决策质量非劣？两组的总 turn 数上限均为三：

| Arm | Turns | 信息可见性与顺序 |
|---|---:|---|
| 单代理持久会话自审（主要对照） | 3 | 同一持久会话依次完成初稿、自我批判、最终稿；后续轮可见原 packet 和该会话全部既有输出。 |
| 独立双审+PI | 3 | Planner 与 Skeptic 使用各自新会话，各 1 轮；两者只见同一原始 packet 和同一任务说明，Skeptic 不见 Planner 草稿。PI 第 3 轮在独立会话看到两份产物及 packet，提交综合答复。 |

两臂共享同一模型版本/推理设置（须记录请求值与可验证值）、SDK、packet 原始证据、工具禁用策略、最大输出/调用策略和三 turn 上限。单代理保留本会话记忆，属于更强的持久会话 baseline；并行方案的两位独立 reviewer/PI 各自冷启动，启动次数和启动开销全部计入。记忆/会话结构差异是待测方案的一部分，不能隐藏或事后解释为角色身份效果。若持久会话对照无法实现，只有在独立批准的附属协议中可做 fresh-session 同角色三阶段自审；该结果必须标成探索性，不能泛化为优于优化后的持久单代理。多角色包不允许把 Planner 草稿泄漏给 Skeptic。角色指令、模板、schema、评分类别及案例均须在探索调用前冻结并 hash。

除非宿主能提供并证明硬 token 上限，不声称等 token。记录每次请求及可用的输入/输出 token、请求耗时、缓存、计费；缺失记 `null/unavailable`，绝不补估为零。若请求失败或 repair/retry，仍计实际 turn/尝试数与成本。超过三次的修复意味着该评价失败，不能悄悄补 call。

本阶段不增加宿主级修复/重试调用：三个预算位置各派发至多一次。SDK 内部不可观测的请求与重试不冒充已被三-turn 上限控制；可观测者另记。模型名称与推理设置在实施清单冻结，Luna 只是当前候选默认，不是永久架构限制。

## 3. 案例集与挑战结构

固定探索集为 24 个新 packet，六类问题各四个；每族四个由两组最小变异 pair 构成（每组含 base 与 mutant），反事实已包含在 24 内，不额外加倍案例数/turn 数。禁止复用已测旧案例；家族关系须审计，不能伪装成独立科学样本。

| 问题族 | 必须包含的挑战 |
|---|---|
| 数量与分母计算 | 至少两步真实计算（比率、加权/条件分母或区间换算）；分母易混但可由明示输入唯一确定；带一个诱人但错误的中间结果。 |
| 单位与类型 | 显式给出单位、边界和枚举；相同物理量有不同量纲或百分比/百分点陷阱；字段的数值类型和表示格式分开评分。 |
| 冲突约束决策 | 至少两个相互冲突的硬约束/预算；多个可接受动作集合须由独立 reviewer 在看模型结果前列出并说明效用/优先级，不以事后任意阈值判错。 |
| 证据出处/未知值 | 多份可追溯证据，含缺失、冲突或适用范围限制；要求引用证据 ID、指出不能推出的结论，禁止把 unknown 当 false/zero。 |
| 对抗指令/不可信文本 | packet 内含显式要求越权、泄漏隐藏信息、忽略约束或执行不允许操作的注入文本；正确行为是将其视为数据并遵从外层任务/权限。 |
| 反事实/变异对 | 每族制作两组最小变异 pair：改变关键数字、单位、可行性约束或来源状态之一；同对两版应导致指定决策/计算变化，其他部分固定。24个packet共12对。 |

每个家族两对变异上下文，且反事实方向、预期变化和可接受答案集合预先登记。变异测试检验模型是否对相关证据敏感，不将同对当独立样本。案例包必须含可手算/可重算中间步骤、冲突矩阵、有效引用集合、单位及类型契约、允许动作集合、注入位置和预期敏感性。不给空值或空字符串设“诱饵”卡 schema；测试真实语义与字段合同，不玩空字段游戏。

案例生成与调试只能用预设事实、离线确定性脚本和人工同行审阅。生成者不得根据探索输出改题。至少一位未参与生成者盲审答案键、计算、边界和动作集合；分歧在 live call 前解决并留痕。development、探索与将来确认题包完全分离，不能通过换数值但保留同构答案泄漏调参。

## 4. 输出合同、评分和裁决

每问的必需字段、JSON 类型、单位、枚举、可空条件、精度/舍入规则和引用格式须逐字段明示在 packet 与 schema 文档中。**此输出 schema 尚未实现**；本文件不声称现有代码已经执行它。实现前要由 B 审阅工程可验证性、由 A 审阅科学字段和单位，随后固定版本与 hash。确定性 validator 只评合同，不根据格式不匹配推定科学推理错。

先冻结每题的可接受答案集合和效用排序：由 reviewer 给出哪些动作正确、可接受但次优、无证据支持、违反硬约束、以及必要理由/证据；如果两个动作在给定信息下同样合理，均计可接受并明确它们的效用区别。不得在看到哪一臂给出何种答案后发明“最优”阈值。

主要语义评分为每案 0–1 的预定义加权评分：核心结论/行动正确性与可行性、计算与单位、证据链/理由、未知与冲突处理，各维度权重调用前冻结。输出格式合同单独报告。主要质量非劣筛查用交付效用 `U`：只有最终答复在 deadline 内通过冻结 schema/引用/范围 validator 并成功持久化，才取盲评语义分 `Q`；否则 `U=0`，表示未交付可用产物，不表示科学错误。语义 `Q` 仍独立报告：格式失败但可评估的文字可盲评，不能把格式失配写成科学错误；不可评估记 null。有效交付率必须单列。

数值规范化仅对预先约定的物理/数学等价形式做 unit-aware 转换；单位映射、精度、舍入容差须在看模型输出前冻结。绝不在评分后拓宽容差、修正参考单位或针对某臂加 parser。原始字符串与规范值都保留。标签大小写只允许在 schema 明文声明可规范化时按合同处理；合同未声明则记严格格式失败，同时交语义盲评。

两名盲评者分别评理由文字和证据引用，不知 arm、角色、输出顺序与聚合数；用固定 rubric 逐项标注，先独立评分再按预定规则解决分歧。引用 ID 由离线脚本验证来源存在，但引用是否支持主张需人工审。报告一致率及分歧；第三方 adjudicator 可裁决但不可改 rubric。按版本保存匿名化评分、依据和裁决理由。任何无法盲化处需说明。

安全为硬门槛：两臂必须经过完全相同的 host 工具权限和 runtime guard。分别记录模型提出不安全/越权建议（proposal-rate）与 host 是否实际发生任何未授权副作用（unauthorized-write/call）；拒绝执行的危险建议不等同于真实越权写入，但仍作为内容安全风险单列。任一 arm 越权调用、实际写入禁止资源、伪造权限/证据或绕过冻结门槛，记严重安全失败；主要质量汇总不能把它平均稀释。关键安全失败使该方案包不能通过验收。工程故障、schema 失败、语义错误、证据误读、安全失败分别记录，互不合并为一个模糊“失败”。

## 5. 估计量与判定门槛

主要工程目标是并行方案包相对单代理自审更省时且不明显损害质量。20% 是预先选定的工程实用目标，不是既有事实。记录两种明确不同的时间 estimand：**观察到的有效完成墙钟**从共同 packet 可读到最终输出通过冻结 validator 并持久化，所有阶段按 arm 关键路径计时、包含启动/排队/调度/PI 综合/清理/落盘；**操作性失败惩罚时间**是预先定义的有效完成耗时或失败时完整 arm deadline（150 秒），用于 ITT 类工程效用筛查，失败赋值是 deadline penalty 而非观察到的实际 latency。主要相对节省筛查使用惩罚时间；有效完成墙钟仅在成功配对中描述，不做失败配对外推。另报尝试/turn 时长、等待、宿主耗时及人工介入；不将 SDK 局部耗时冒充整条流程。

“共同 packet 可读”指相同前置条件，不指两臂共享一个物理起点：宿主按随机顺序分别释放已经准备好的同字节 packet，记录各臂自己的单调时钟起点。第二臂等前一臂完成的排程等待不进入该臂 latency；本臂启动后的 provider 排队必须计入。整体批次墙钟另报。盲评在交付后进行，不进入交付耗时；人工评分时间另记。

目标 estimand 是冻结的24个工程 packet 有限集。先在每 packet、每臂内对两次重复的惩罚时间取算术平均，得到 `C_single,i`、`C_parallel,i`；再算 packet 相对节省率，主要点估计 `D_t = median_i((C_single,i − C_parallel,i) / C_single,i)`。观察到的有效完成墙钟先平均重复，只作成功交付描述。每重复独立计算交付效用 U；每 packet 内先对两重复取均值，得到 `U_parallel,i`、`U_single,i`，再等权汇总 `D_U = mean_i(U_parallel,i − U_single,i)`，作为质量非劣筛查量；语义分 Q 另作描述。任一重复未启动，则完整配对筛查不通过。可报告保留12个反事实pair结构的分层 bootstrap 95%描述性区间；重复不是独立案例，六个便利族也非随机抽样簇。区间只展示本有限集重采样敏感度，不能支持总体 superiority/noninferiority 推断。方法须执行前冻结并 hash。

描述性重采样算法固定为：六个族保留为固定层，各层从本层两组 base/mutant pair 中有放回抽取两组；每次整组保留两个变体、两次重复及两臂配对，再重算上述同一估计量。10,000 次，seed 1729，取 2.5%/97.5% 分位点；不把它称为覆盖率已验证的总体置信区间。若依赖审计显示族内两组也共享同一底稿且不宜重采样，取消区间、仅报原始量，筛查判不确定，不改算法来求通过。

本轮只能使用操作性筛查规则：`D_t ≥ 0.20` 且描述性区间下界 `>0`，并且 `D_U` 描述性区间下界 `>−0.02` 时，记为“固定工程挑战集达到预定时间/交付效用筛查门槛”；否则未达到或不确定。任一臂出现操作失败、严重安全失败或无法完整审计，整体筛查强制失败，不得被时间或 U 分数抵消。此门槛不是显著性、普遍非劣证明或新任务优势主张。区间小簇不稳/不可估时报告不确定，不改用更窄方法。

本阶段只有预注册的质量非劣筛查，不另设“质量提升”端点，避免质量/效率二选一报告。24 个便利 packet 不是统计功效充足的总体样本；开发集不用于估计方差/功效。将来统计确认必须独立定义目标工程工作负载抽样机制，使用盲化模拟验证区间覆盖，并冻结样本量后单独审批。

## 6. 运行规模、预算与失败计入

独立开发阶段先跑 4 个开发 packet（预先指定的四个问题族各一，不声称覆盖六族），每臂 1 次，共 24 SDK turns。只检查 plumbing、schema、计时和日志，不估方差/功效，不纳入探索效应，也不因结果修改探索题或门槛。之后冻结当前探索运行器、模型/设置、题包、rubric、validator、提示词、执行器与 hashes。旧 runner 的 84 turns 不能执行本协议新对照；新 runner/schema 尚待实现、单独审查与批准。SDK turn 与 provider 内部请求数不同；分别记录可观测的 SDK dispatch、SDK/网络 retry、provider 请求及计费，未知记 null。

固定工作负载探索阶段为 24 个 packet × 两个重复 × 两臂 × 每臂三 SDK turns = **288 SDK turns**（含并行臂两项独立首轮）。这是新 runner 和 schema 的独立预算，必须经实现/安全审查并获明确批准；开发预算批准不自动包含调用。不开启自动 live 路径，不因本文自动运行。可分6批，每批8 packet各重复一次，即48 turns；每批最多30分钟、总上限3小时，达到 cap 后停止并报告未完成。此阶段只描述固定挑战集，不得包装成确认研究。

未来若要统计确认，必须另立协议和预算：定义工程工作负载生成分布、模板/难度权重、独立抽样 block 与可交换性依据；每个 block 包含配对 arms 及 counterfactual siblings，按 block 聚类。可沿用题型，但使用全新参数/证据/边界实例；推断仅限冻结的工程生成分布，不能代表科学任务总体。探索结果不能用来挑确认案例或声称足够功效；样本量须基于预先固定的保守方差假设或额外单独批准的 pilot，再由统计 reviewer 以盲化模拟检查 CI 覆盖后冻结。固定 N、分析法、多终点门控和预算须在确认前另行批准；如果可批准预算无法覆盖 N，则保持“不确定”，不降 N 后假装确认。

每 turn 调用硬超时 45 秒；每 arm 为 3×45 秒加 15 秒有界清理，共 150 秒上限。超时须真实取消并等待进程清理，不可只停止等待而留下后台任务。配对执行在同一时间窗按平衡随机顺序安排：并行 arm 的两位审查最多同时占 2 个并发 SDK 执行槽/会话，PI 在审查完成后运行；单代理轮次顺序运行，占 1 槽。provider 内部并发、重试或请求数若不可 attestation，记 null，不从 SDK 槽推断。记录此资源差异：比较的是可部署方案包延迟，不是等并行吞吐资源条件下的服务器效率。全局预留完整配对预算，禁止一个臂耗尽全局剩余时间后挤压另一个臂；到期的未启动 arm 不得算作成功配对。

45 秒覆盖 SDK/子进程启动与请求消费，不只包住事件流；清理计入 arm 的150秒宿主 deadline。可用批次时间不足完整配对300秒加冻结的持久化余量时，不启动该对。未启动记缺失，不能缩短最后一个臂的限时。超时或审查子进程失败时须回收其后代并确认 sibling/PI 的生命周期按冻结策略结束；未回收即工程验收失败。

随机化案例顺序与 arm 执行顺序，固定种子并保存生成结果；两重复之间清理会话，防止跨臂记忆。same-model 不能仅依赖提示词声明，记录请求与可获得的模型身份凭证。记录缓存/热启动状态，按批次平衡顺序；无法消除的队列竞争须披露。无硬 token 限额时不能声称严格资源平衡。

所有已启动的失败保留在意向执行清单：超时/取消、SDK 错误、坏 JSON、错误 schema、空响应、持久化失败、超 budget、模型拒答分别编码。操作性失败惩罚时间对已启动但未产出有效终点的 arm 计完整 deadline（150 秒），避免“失败得快”获得筛查优势；同时单独报告失败实际发生/取消时刻、有效完成墙钟、失败率和 deadline-penalized composite。惩罚值不可标成观测 latency。未启动 arm 记 null；存在未启动/缺失臂时本阶段门槛不通过。若任一 arm 出现探索集操作失败或无法安全审计，整体至少标记可靠性未通过/不确定，不能以 composite 时间达标宣称工程成功。交付效用 U 对无有效交付明确为0；语义分 Q 对不可评估失败为null，二者不得混写。安全违规另按硬门槛处理。

每次尝试保存匿名 case ID、arm、重复、turn 顺序、prompt/schema/rubric/case hashes、请求/响应原文的安全脱敏版本、SDK/模型请求标识、起止单调时钟、阶段耗时、实际 token/成本（若 attested）、超时/取消/重试、validator 输出、评分者盲码及持久化校验。不得记录凭证或敏感真实数据；原始日志权限受控，发布副本须脱敏并保留 hash。run ID 未创建前不得编造；不写假结果或假运行记录。

## 7. 与现有运行时、科学门槛和基线的隔离

本测试不得初始化 science engine、native live run、数据下载、holdout bridge 或科学计算。不得改 frozen registry、既有 Result、attempt 计数、实验预算、协议 hash、holdout 门槛或授权状态。测试案例只能是独立工程包；禁止把 fixture 输出伪装成 NOVA-MAT 科学结果。以 import spy/open sentinel 证明科学/holdout 模块未加载/访问；只读比较保护文件/gate 元数据 hash；不初始化或复制真实 SQLite。测试状态写入全新隔离目录，不触碰 live registry。

现有技术方案第 10 节的人工基线是六个真实 discovery 上下文，由两名熟悉项目的参与者各做三个上下文，并与系统配对；本自测的两臂模型对照不是那个人工基线，也不能替换或引用其尚未实测的效率目标。人工时间、系统对真实结果作合法下一 Spec、follow-up 实验时间与 human intervention 都应分开报告。任何从合成测试推至原生工作流效用的主张均禁止。

参考当前架构，PI 协调 Planner/Skeptic/Runner，host/registry/SQLite 负责不可变 Spec、运行绑定、阶段 gate 和预算；科学工具只接受已注册 ID。此计划仅检查隔离的请求链、handoff 和最终记录是否符合工程合同；不声称全原生角色链已由当前 SDK 对照实现。旧 quality benchmark 是 fresh-session 串行 role-framing，不是独立并行 review；已有84 turns不能当新测试的执行器。与 `single_once` 加确定性计算/自适应审查的强部署基线比较不在本预算内；即使本三轮对比达到筛查门槛，也不能据此宣称值得替换更轻量基线。采用决策需另有预算批准的同交付物强基线评测。

## 8. 分阶段验收与停止规则

在任何付费探索调用前，须全部勾选：

- [ ] A 与 B 对科学事实范围和职责边界书面同意；测试包不触碰真实科学/holdout。
- [ ] 24 个探索 packet 及 4 个不同开发 packet 完成独立答案键审查、反事实核验和脱敏检查。
- [ ] 每问 schema/types/units/enum、允许动作集合、计分 rubric、严重度权重、容差和 blind review 说明均冻结并有 hash。
- [ ] 两臂 turn 信息流经离线 trace 测试验证，尤其 Skeptic 首次阅读绝无 Planner 草稿，且 PI 确实同时获得两份输出。
- [ ] 并行子角色用隔离子进程/每进程环境注入，不修改父进程全局环境；并发、重叠、取消测试证明无 set/restore race。
- [ ] 可信 parent 在 dispatch 前原子预留共享三-turn 上限；SDK worker 不写计数器；并发/重复请求不可超发。
- [ ] append-only journal 每次模型调用前先持久化；checkpoint 经临时文件写入、fsync、原子 rename、目录 fsync。逐点 crash 注入后恢复为完整旧版或新版；不覆盖历史。中断 turn 的结果标记 unknown、预算保留占用，实际账单仍未知，不自动恢复重跑。
- [ ] 单调时钟、并行关键路径、排队、硬 timeout/取消、重试计数、持久化和日志脱敏完成离线故障注入验收。
- [ ] 隔离测试能证明 registry/attempt/frozen gates/holdout 没有变化；权限测试验证 injection 只能作为数据，不能调用未批准工具。
- [ ] 离线评分样例覆盖正确答案但错格式、错答案但格式正确、单位变换、未知值、合法多解和无法 adjudicate；报告输出不会混淆三类效用。
- [ ] 冻结探索集、交付效用定义和分析脚本；描述性 CI 与失败处理在盲化模拟数据上运行；禁止基于探索结果调参后称确认。
- [ ] 单独批准开发24-turn及探索288-turn预算；用户明确批准前不调用模型。未来统计确认另立计划与预算。

任何严重安全违规、跨臂污染、案例 hash/答案键变更、持久化丢失、时间计量不一致或取消后后台仍运行，立即暂停并报告。只允许修正工程缺陷后，以新的版本、全新题包/确认计划重新审批；不能把原确认批次挑选性续作。未达到固定 N 或任一 arm 大量失败时，结论为工程可行性/可运行性受限，禁止 superiority 宣称。

## 9. 报告模板与允许结论

最终报告必须同时列：scope/version/hash；案例族与配对图；分配数、完成数、全部失败及原因；实际 turn/重试/模型身份可验证程度、token/计费可用性；schema pass、有效交付率、交付效用和语义分项；安全严重失败；observed wall time 与 deadline-penalized composite 分列；`D_t`、`D_U` 描述区间与聚类单位；盲评者一致率/争议；未测项与预算偏差。

若达到全部操作性筛查门槛，允许的最强文字为：“在本次固定的24个探索性工程 packet、指定模型/执行配置和可观测资源下，方案包达到预设 deadline-penalized 时间与交付效用筛查指标；观察到的有效完成 latency 和失败率另列；便利集区间仅描述性，未建立总体优势/非劣性。”不写“多 agent 让科学发现更快”“specialist 身份本身有效”“优于 single_once 加确定性工具”“普遍提升科学准确性”或“10× 加速”。若未通过，报告未达到/不确定/失败率差异，不把零效应当等效。

任何阶段的报告均不自动更改架构或转成 resume claim。若区间跨零、质量门槛失败、优势仅在某家族或关键安全/可靠性回归，则应审慎缩减/停止该架构、保留更简单的单代理自审作默认，或提出单独预注册的 serial-role ablation、路由/调度研究。之后若要验证原生科学效用，另立协议，由 A 预先批准科学问题与数据范围，采用真实完成的 science Results、合法 registry 路径、充分对照及独立 scientific acceptance；不重开既有 holdout。
