# Discovery workflow baseline comparison

Status: declared engineering benchmark design, not measured results. This
plan was written after observing the scientific findings and is not a new
scientific preregistration. It does not change any frozen representative,
split, gap window, threshold, method protocol or holdout authorization.

## Common question and inputs

Compare the cost and useful evidence produced by three ways to respond to
the same completed discovery primary Result: an adaptive agent workflow,
a fixed rule and all feasible diagnostics. Use identical prepared-data and
protocol bytes, seed 1729 and 2,000 bootstrap repeats. Keep OPT's inclusive
1.1–1.8 eV window and primary 0.05 eV/atom stability limit. The threshold
diagnostic reports every fixed point (0.025, 0.05, 0.10); the exploratory
method diagnostic pairs OPT/MBJ on identical frozen representative JIDs.

Each arm needs its own legal native registration and attempt state. Compare
the same scientific parent fields and frozen provenance; record the actual
run/Result IDs, which can differ between runs. Never import portable events
to manufacture authorization, reopen a failed attempt, or clone a final
holdout claim. This benchmark is discovery-only and executes no holdout.

Publish the context and feasible-action packet before timing a matched
group. Use the same deadline and science budget for all arms. A host estimate
such as 60 or 120 seconds is planning metadata, not a measured duration.

## Policies to implement and label

| Arm | Declared policy | Recorded evidence |
| --- | --- | --- |
| Adaptive | Actual model roles review the primary evidence, choose a legal diagnostic or stop, receive any new Result, and continue/stop with cited evidence. | Competing options, choice/rationale, real independent critique, returned function result, final decision and full model trace. |
| Fixed rule | Take `threshold_sensitivity` if host-feasible; otherwise `method_sensitivity` if host-feasible; otherwise stop. No model call. | Exact rule/version, feasible packet, chosen action, resulting facts and host-generated summary explicitly labeled as such. |
| Run all feasible diagnostics | In the fixed order threshold then method, execute each legal diagnostic once under the common budget; report every outcome and any action not dispatched. No model call. | Both diagnostic reports where allowed, individual authorization/attempt records, total cost/time and missing-evidence inventory. |

B must provide the legal registration/execution path for the run-all arm.
The current one-follow-up native shape cannot be bypassed by direct calls
to a low-level science function. Until that path exists, run-all is an
unexecuted benchmark arm. Do not broaden A's existing method exporter merely
to accommodate an imagined run shape.

## What to measure

Use [the pending measurement template](examples/baseline_measurement_template.json)
for each arm. Keep these boundaries distinct:

| Measure | Boundary or rule |
| --- | --- |
| Primary setup | Fresh registered run through completed primary Result; reported separately for every arm. |
| Follow-up wall time | Before option/reviewer/policy dispatch through the saved final decision/report. Includes model queueing, all turns/repairs, science startup, validation, persistence and final export. |
| Total wall time | Before fresh run setup through the same terminal artifact. Report both this and follow-up wall time; do not substitute kernel time. |
| Science compute | Actual worker computation for each diagnostic, with startup/host overhead separately reported where recorded. |
| Model usage/cost | Every attempted turn, failure, retry and repair. Preserve provider usage and actual billing evidence; unknown usage or billing is `null`, never zero. Distinguish requested from attested model identity. |
| Human time | Record observed operator setup/intervention separately if measured. A scripted science duration cannot substitute for a manual baseline. |
| Evidence coverage | Threshold points reported; method arms/contrast; candidates and unknown comparators; any diagnostic omitted by choice or budget. |
| Scientific correctness | Actual references, counts, units, nulls, frozen statuses and next-step advice agree with their source. A structured pass does not validate every rationale sentence. |

Record environment and cache mode. Prefer fresh authorized runs with no
completed-result cache hits within a matched group. If comparing cached
evidence, put every arm in a separately labeled cached group and include
the cost of obtaining that evidence. Shared OS caching, warm model sessions
and service queue variation must be disclosed; alternate arm order across
groups rather than always warming the adaptive arm last.

## Acceptance and interpretation

A scientific component can succeed while the workflow fails. The latest
native attempt persisted two valid scientific Results and then failed
feedback; its workflow is a failure. Keep cancellation, timeout, invalid
review, missing model usage, packaging failure and legal stop as distinct
outcomes. Preserve failed attempts and their spent time/cost. A legal stop
must not count as a completed diagnostic or be used to win a diagnostic-time
comparison simply by doing no work.

Check each arm against the same scoped deliverable: correct primary evidence,
a legal declared next-action policy, all dispatched diagnostic results
accounted for, and a final factual report with its evidence coverage and
limitations. Additional agent-specific acceptance requires the independent
model review, Result return and evidence-dependent final decision. Those
requirements are reported separately from the rule/run-all baseline's
host-generated summaries.

Report raw matched timings and evidence coverage together. An adaptive arm
that skips the method diagnostic has less method evidence than run-all;
that is a measured tradeoff, not proof of equal-work acceleration. Count
choice value only where the final report identifies the uncertainty addressed
and cites the result that changed the next decision. Do not infer utility
from the number of agents or a preferred narrative.

Aim for six matched engineering contexts; with fewer than three valid matched
groups, report raw observations only. With at least three, any ratio remains
descriptive for the measured contexts and requires comparable completed
deliverables. Repeated executions of this snapshot are engineering repeats,
not independent scientific samples. If native failures prevent the complete
comparison, publish that limitation without an acceleration or cost-saving
claim.
